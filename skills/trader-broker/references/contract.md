# Черновик и журнал

Вход — полный пакет из контракта `trader-risk`, включая фактические данные для повторного расчёта, а не готовое утверждение о прохождении риска. Пример: [example.json](example.json).

Для черновика дополнительно нужны `instrument.ticker`, `instrument.class_code` и `identity_verified: true`: проверенное соответствие тикера/режима торговли UID. Его нельзя угадывать по имени компании. Все цены нормализованы в валюту расчётов, поэтому черновик явно задаёт `PRICE_TYPE_CURRENCY` и не передаёт проценты номинала облигации как рубли.

Результат содержит `risk`, список `drafts` с `draft_parameters`, отпечаток каждого черновика и постоянный `execution_enabled:false`. При изменении исходного пакета меняется `risk.bundle_fingerprint`, риск пересчитывается. Отпечаток черновика меняется только при изменении его параметров. Наличие отпечатка не является подписью брокера.

Журнал JSONL сохраняет только время подготовки, статус, отпечаток исходного пакета и отпечатки черновиков. В нём нет статуса «исполнено», ожидаемых налоговых лотов или предположения о заполнении заявки. Для фактических сделок потребуются отдельно проверенные данные брокера на следующем этапе, без использования черновиков как доказательства.

Справка о формах методов: [OrdersService](https://developer.tbank.ru/invest/services/orders/methods). На этом этапе методы не вызываются.
