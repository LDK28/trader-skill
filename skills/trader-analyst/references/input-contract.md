# Нормализованные отчётные факты

Вход: `{as_of,companies:[{uid,class_code,ticker?,name?,availability?,reports:[...]}]}`.

Отчёт содержит:

- `standard`: `IFRS` или `RSBU`; `scope`: `consolidated` или `standalone`.
- `currency`: код валюты; `period_start`, `period_end`: даты включительно.
- `period_type`: `quarter`, `half_year`, `nine_month`, `year`; длительность проверяется.
- `flow_basis`: `discrete` или `year_to_date`. По умолчанию квартал и год считаются дискретными, полугодие и девять месяцев — накопленными; передавай поле явно, когда источник устроен иначе.
- `published_at`: время с часовым поясом; `source_url`: ссылка на прочитанный первичный отчёт; `restated?`.
- `metrics`: `revenue`, `gross_profit`, `operating_income`, `net_income`, `eps_basic`, `eps_diluted`.

Каждая метрика — `{value:"120",unit:"money",currency:"rub",scale:"1000000"}`. Числа — конечные десятичные строки. Для EPS unit=`money_per_share`; валюта должна совпадать с отчётом. `scale` по умолчанию `"1"`: если источник в миллионах, это необходимо явно отразить. Показатели во входе — только значения из отчёта, не прогнозы.

Производные значения имеют `derived:true`; маржа и рост имеют unit=`percent`. Отрицательная или нулевая база прошлого периода не даёт осмысленного обычного процентного роста: поле пропускается с пояснением. Для квартального TTM нужны четыре непрерывных дискретных квартала на той же базе; сопоставимость базы акций для EPS отдельно не устанавливается.

Публикации и пересмотры после среза не используются. Поля источников сохраняют происхождение, но программа не проверяет содержимое ссылки. Пример полностью искусственный.
