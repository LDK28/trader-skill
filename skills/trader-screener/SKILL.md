# Проверяемый отбор

Согласуй критерии отбора и передай их в `scripts/screen.py`. Скринер работает только с поданными JSON-данными и не ищет цены, отчёты или инструменты самостоятельно.

```bash
python3 scripts/screen.py references/screen.example.json --output SHORTLIST.json
```

Прочитай [контракт](references/input-contract.md). Используй канонические `uid` и `class_code`, единый срез `as_of`, одну явно выбранную базу отчётности. К показателям аналитика присоедини отдельные сведения о доступности API, счёту и денежному режиму. Каталожный флаг API сам по себе не подтверждает доступность клиенту и не доказывает возможность купить за собственные средства.

Отсутствующие метрики, несовместимые единицы или валюты, неподтверждённая доступность и публикации из будущего дают отказ с причиной. Не превращай отсутствие в ноль и не отключай правило, чтобы получить проходящий список. Банковские, страховые, облигационные и фондовые показатели сравнивай по подходящей методике; P/E эмитента не является универсальным фильтром всех активов.

Ранжирование — взвешенные относительные места среди прошедших отбор; это не вероятность прибыли, целевая доля или торговое поручение. Выход `shortlist` сохраняет UID и класс; распределение денег выполняется отдельным бюджетным модулем. Не выдавай сегодняшнюю доступность за историческую при ретроспективном отборе.

Соседний `trader-tinvest` обязателен. Навык не меняет брокерский счёт и не исполняет сделки.
