# Статус функционального переноса

Дата карты: 09.11.2026. Проверенный upstream: `5189e79b9a480755a3733ac9713f5353981dbe18`. В `skills/` находятся 11 тематических навыков и координатор `trader-tinvest`. Для каждого тематического навыка есть отдельный SKILL, исполняемый CLI, контракт JSON, искусственный пример и тесты. Все папки устанавливаются соседями; общие помощники находятся в координаторе.

## Уровни готовности

| Уровень | Состояние текущего пакета |
|---|---|
| Функциональная российская реализация задач всех 11 модулей | Есть в заявленном офлайн-контракте; предмет и ограничения каждого модуля указаны ниже |
| CLI, искусственные примеры и тесты | Доступны без сети, токенов и счёта; полная команда проверки — в README |
| Упаковка исходников | `scripts/package_skills.py` сохраняет 12 папок и общие зависимости; не публикует пакет и не переносит авторизацию |
| Фактические российские источники/извлечение документов | Нужны отдельные интеграционные проверки полноты, схем и времени доступности |
| T‑Invest MCP и нормализация ответов конкретного сеанса | Не подтверждаются офлайн-тестами; REST-профиль нормализатора не равен MCP-адаптеру |
| Стратегия и рыночное преимущество | Не устанавливаются этой фазой; исследовательские инструменты координатора необязательны |
| Исполнитель заявок и автоматическое расписание | В текущем пакете не реализованы |

## Что именно покрывают модули

| Навык | Офлайн-результат | Что остаётся вне результата |
|---|---|---|
| copycat | Исторические веса, сравнение сопоставимых составов, нормализованные цели | Полный загрузчик российских фондов, текущие сделки управляющего |
| news | Нормализация сохранённых лент, источники, время, дедупликация | Постоянный сбор и независимая проверка каждой новости |
| budget | Распределение бюджета с лотами и заданной моделью издержек | Подтверждённая брокером стоимость и готовый риск-пакет |
| pelosi | Индекс публичных раскрытий российских эмитентов/владельцев, новые версии, диапазоны | Реестр сделок политиков РФ, полный US PTR-парсер, полнота всех раскрытий |
| analyst | Сопоставимые метрики переданной МСФО/РСБУ | Универсальное извлечение фактов из отчётов всех эмитентов |
| screener | Правила, ранжирование и объяснение пропусков/отказов | Выбор стратегии, гарантированная доступность и качество будущих метрик |
| risk | Общие проверки нормализованного пакета, своих денег/бумаг, дневного контроля и лимитов | Аутентичность брокерских данных, резервирование, исполнение |
| broker | Повторный контроль, параметры и журнал DRAFT_ONLY | Отправка, изменение, отмена, фактические исполнения и налоговые лоты |
| tax | ФИФО/RUB, комиссии, исторический FX, отдельные годы/корзины | Полный налоговый движок РФ, автоматическая база, ИИС, льготы и US wash sale |
| alerts | Заданные условия, пересечения, состояние, переданные интервалы биржи | Создание расписания, доставка уведомлений, знание непереданного календаря |
| rebalance | Отклонение от явных целей; отдельный расход своих денег и своих свободных бумаг | Финансирование ожидаемыми продажами и автоматические операции |

Цепочка `copycat → budget → risk → broker` или `analyst → screener → budget → risk → broker` задаёт смысл работы, а не взаимозаменяемость JSON. Каждое преобразование требует проверки контракта, UID, валют, времени и источников. Результат одного модуля не становится подтверждённым входом следующего простым добавлением `verified:true`.

## Проверка среды после установки

Проверьте наличие всех 12 `SKILL.md`, соседский путь к `trader-tinvest/scripts`, Python 3.9+, `--help` тематических CLI и искусственные примеры. Затем выполните офлайн-тесты. Без доступной среды Python можно читать инструкции, но нельзя заявлять выполненный CLI-расчёт.

В ChatGPT импорт многомодульного ZIP выполняется только через поддерживающий такой формат интерфейс и с проверкой зависимостей. Вложение ZIP, публикация GitHub и наличие метаданных плагина сами по себе не подтверждают установку в конкретном клиенте или публикацию в каталоге. Сборка и установка не переносят MCP-токен, доступ к счетам или права пользователя.

Личные параметры остаются в `policy.local.json`, реальные входы/история, состояния и журналы — вне публичного Git. Публичный policy и все опубликованные примеры искусственные либо демонстрационные; они не фиксируют согласие нового пользователя.
