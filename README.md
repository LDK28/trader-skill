# Trader Skill для Т‑Инвестиций

Навык Codex для чтения портфеля через официальный T‑Invest MCP, ежедневного анализа и подготовки расчётного торгового плана. Покупки рассчитываются только за собственные деньги, с учётом лотов, комиссий и блокировок.

## Что готово

- **Один навык `trader-tinvest`**: инструкции по работе с портфелем, источниками данных и ежедневным обзором.
- **`cash_guard.py`**: офлайн-проверка бюджета предложенных покупок `BUY/LIMIT` по нормализованным данным.
- **`sell_guard.py`**: офлайн-проверка количества для `SELL/LIMIT` только из собственных свободных бумаг; общий остаток и лимит проверяются на весь пакет продаж.
- **`daily_loss.py`**: офлайн-проверка дневного убытка с отдельным учётом пополнений и выводов.
- **`normalize_broker.py`**: первый слой нормализации сохранённых REST-ответов — точные числа, позиции, метаданные, собственные лимиты и происхождение данных. Результат — наблюдения с `ready_for_validators: false`, без автоматического подтверждения собственности, расчётов и отсутствия долга.
- Тесты расчётных ограничений.
- **`backtest_breakout.py`**: офлайн-прототип одной гипотезы на одной акции с полной оплатой, лотами, издержками, частичными продажами и разделением development/holdout. История не загружается; прибыльность не установлена.
- [Протокол исследования стратегии](skills/trader-tinvest/references/strategy-research.md): данные, правила сигнала, проверочный период, издержки и критерии отклонения гипотезы.

Для исследования реализована гипотеза пробоя, но она не выбрана для реальной торговли и не проверена на подтверждённой рыночной истории. В пакете нет исполнителя реальных сделок, полной проверки стоимости/комиссий продаж, проверенного адаптера фактических ответов MCP с полной сверкой входов для валидаторов или созданного ежедневного расписания. Офлайн-нормализатор REST и бэктест не заменяют эти части. Успешные тесты проверяют арифметику и ограничения, а не прибыльность. Прибыль не гарантируется.

Проект использует [исходный trader-skill](https://github.com/jakeschincariol/trader-skill) как методический ориентир. Его 11 модулей не установлены и не перенесены целиком. [Разбор исходного кода](skills/trader-tinvest/references/upstream-review.md) фиксирует проверенный коммит, ограничения переноса и очередь разработки.

Краткосрочная торговля и шорт — разные режимы. Покупка за собственные деньги с последующей продажей своих бумаг совместима с запретом займа. Шорт заёмных бумаг требует другого учёта обязательств и риска; текущая версия его не поддерживает. Для продаж собственных бумаг проверяется только доступное количество, без расчёта будущей выручки.

## 1. Установка в Codex

В Codex отправьте:

```text
$skill-installer Установи навык trader-tinvest из репозитория https://github.com/LDK28/trader-skill, путь skills/trader-tinvest.
```

Если новый навык не появился, перезапустите Codex. Для явного вызова используйте `$trader-tinvest`; в интерфейсе с выбором навыков через `@` выберите его в списке. Подробнее: [официальная документация навыков Codex](https://learn.chatgpt.com/docs/build-skills).

Для самостоятельного запуска расчётных скриптов нужен **Python 3.9 или новее**. Скрипты и тесты используют стандартную библиотеку Python; устанавливать дополнительные зависимости не требуется.

## 2. Подключение Т‑Инвестиций

1. Выпустите токен **«Только просмотр» / read-only**, по возможности для одного нужного счёта.
2. В настройках MCP Codex добавьте сервер с именем `t-invest`, транспортом **Streamable HTTP** и URL [https://invest-public-api.tbank.ru/mcp](https://invest-public-api.tbank.ru/mcp).
3. Настройте авторизацию заголовком `Authorization: Bearer <TOKEN>`, подставив токен только локально в настройки подключения.
4. Сохраните подключение и перезапустите MCP-сервер. Убедитесь, что его инструменты появились в Codex.

Если интерфейс предлагает поле **«имя переменной окружения для Bearer-токена»**, в нём указывается имя, например `TINVEST_TOKEN`, а не сам токен. Значение этой переменной должно быть доступно процессу Codex. Не смешивайте такой способ с вводом готового заголовка авторизации.

Токен хранится вне репозитория. Не добавляйте его в чат, JSON-примеры, снимки данных или коммиты. Для этой версии не нужны права на торговлю и переводы.

Официальные инструкции: [T‑Invest MCP](https://developer.tbank.ru/invest/mcp), [подключение ИИ-клиентов](https://developer.tbank.ru/invest/mcp/agents-connect/coding-agents), [права токенов](https://developer.tbank.ru/invest/intro/intro/token).

## 3. Как пользоваться

Проверить подключение и увидеть портфель:

```text
$trader-tinvest Проверь подключение. Покажи доступные брокерские счета, затем состав выбранного портфеля, собственные деньги и блокировки с временем данных.
```

Подготовить ежедневный обзор:

```text
$trader-tinvest Выполни ежедневный пересмотр по policy.json: оцени портфель, дневной результат после внешних денежных потоков, новости и кандидатов. Покажи источники, издержки и недостающие проверки. Сделки не исполняй.
```

Разобрать новости выбранных бумаг:

```text
$trader-tinvest Собери новости по указанным мной эмитентам за последние сутки. Укажи даты и источники и отдели факты от возможных последствий для портфеля.
```

Проверить расчётный план:

```text
$trader-tinvest Проверь предложенный мной план покупок: собственные деньги, целые лоты, доступность инструментов, комиссии, НКД, блокировки и дневной порог. При неполных данных покажи, почему проверка не пройдена.
```

Проверить количество для продаж собственных бумаг:

```text
$trader-tinvest Проверь весь пакет SELL/LIMIT через sell_guard.py: собственные рассчитанные позиции, блокировки, лоты, UID и лимит sellLimits. Не учитывай выручку в бюджете покупок. Отдельно покажи непроверенные комиссии, дневной риск и исполнимость. Сделки не исполняй.
```

Если подключение отсутствует, навык должен сообщить об этом. Он не может восстановить личный портфель из публичных котировок. Если стратегия или её данные не проверены, корректный результат — список недостающих проверок, а не обещание дохода или готовой покупки.

Начать разработку проверяемой стратегии:

```text
$trader-tinvest Подготовь паспорт одной краткосрочной гипотезы по протоколу strategy-research.md: правила входа и выхода, нужные данные, разделение истории и проверочного периода, модель издержек и причины отказа. Отдельно укажи, что уже проверено. Доходность и результаты тестирования не выдумывай; сделки не исполняй.
```

## 4. Параметры ежедневного режима

Пример профиля находится в [policy.json](skills/trader-tinvest/references/policy.json), процедура — в [daily-review.md](skills/trader-tinvest/references/daily-review.md). Перед персональным планированием согласуйте параметры в чате. Для сохранения своих параметров можно создать рядом `policy.local.json`; этот файл исключён из Git. Поля `profile_kind: "example"` и `requires_explicit_adoption: true` обозначают, что публикуемый пример не является согласием пользователя на такой риск.

| Параметр | Значение в примере |
|---|---|
| Пересмотр | Ежедневный, время Europe/Moscow |
| Перенос позиций | Разрешён |
| Бюджет | Весь подтверждённый доступный собственный остаток; комиссии и округление учитываются |
| Маржа, займы, шорты и плечо | Запрещены |
| Дневной порог | При убытке ≥50% прекращается подготовка новых предложений |
| Реальное исполнение | Отключено |
| Расписание | Не создано |

**50% — высокий демонстрационный порог, а не рекомендуемый универсальный риск.** Используйте согласованное вами значение. Порог останавливает новые предложения, но не закрывает позиции и не гарантирует максимальный фактический убыток. Пополнения не считаются прибылью, выводы — убытком; база контроля равна капиталу на начало дня плюс сверенный чистый внешний поток. При недостающей базе или потоках новые предложения блокируются.

Проверьте отключение маржинальной торговли в настройках самого брокерского счёта. Заявление пользователя об отключении и результат проверки через API — разные источники сведений. Расчётное предложение всё равно требует подтверждённых собственных доступных средств и полной стоимости. Изменение поля в JSON не меняет настройки счёта у брокера.

Для анализа можно рассматривать весь доступный каталог. Денежный валидатор поддерживает только подтверждённые покупки акций, облигаций, фондов без плеча и спот-валюты с полной оплатой. Производные инструменты, неизвестные обязательства и продажи не проходят этот валидатор. `sell_guard.py` отдельно проверяет собственное свободное количество акций, облигаций и фондов без плеча; спот-валюта и производные в нём не поддерживаются. Полное использование бюджета не обязывает формировать сделки при отсутствии подходящей проверенной гипотезы.

## 5. Расчётные скрипты

Из корня клонированного репозитория:

```bash
python3 skills/trader-tinvest/scripts/cash_guard.py --help
python3 skills/trader-tinvest/scripts/sell_guard.py --help
python3 skills/trader-tinvest/scripts/daily_loss.py --help
python3 skills/trader-tinvest/scripts/normalize_broker.py --help
```

Справка содержит схемы нормализованного JSON. Скрипты не подключаются к брокеру: вызывающая сторона должна собрать и сверить данные, идентификаторы, валюты, время и полную стоимость. Десятичные суммы передаются строками, например `"123.45"`, а не числами с плавающей точкой. Флаги подтверждения являются утверждениями нормализатора, а не самостоятельным доказательством достоверности данных.

```bash
python3 skills/trader-tinvest/scripts/cash_guard.py .local/cash-plan.json
python3 skills/trader-tinvest/scripts/sell_guard.py .local/sell-plan.json
python3 skills/trader-tinvest/scripts/daily_loss.py .local/daily-risk.json
```

Эти локальные JSON-файлы нужно подготовить по схеме; команды не создают их автоматически. Для `cash_guard.py` данные быстро устаревают: снимок — не старше 60 секунд, котировка и оценка стоимости — не старше 30 секунд. Не обновляйте метки времени без повторного получения исходных данных.

Для `sell_guard.py` снимок также не старше 60 секунд, котировка и `position_limit` — не старше 30 секунд. `settled_own_units` — собственное количество после расчётов, **включая** `blocked_own_units`; оба поля исключают заёмные бумаги и ожидаемые поступления. Свободный остаток равен их разности. Если семантика блокировки неизвестна, вход не подтверждён. Повтор UID в снимке блокирует проверку.

Все предложения продажи одного UID используют один остаток. Суммарные лоты дополнительно ограничиваются минимумом подтверждённых `sellLimits.sellMaxLots`, а не суммой повторных ответов. В `position_limit` сверяются счёт, UID и цена. Поля `limit_price` в этой схеме выражены в единицах цены `GetMaxLots` и одной валюте расчётов; для облигаций этот метод принимает денежную цену, а рыночная котировка может быть в пунктах. Нормализатор должен проверить преобразование — скрипт его не выполняет. См. [документацию лимитов](https://developer.tbank.ru/invest/services/orders/methods) и [единиц цены](https://developer.tbank.ru/invest/intro/useful-info/points).

Проверка продаж не рассчитывает комиссии, НКД, выручку, дневной результат или исполнение и не резервирует бумаги. Пакеты BUY и SELL проверяются отдельно; выручка от предполагаемой продажи не пополняет доступный бюджет BUY. Перед новым обзором нужно обновить данные и учитывать все ещё актуальные предложения вместе, чтобы не использовать позицию повторно между запусками.

| Скрипт | Результаты |
|---|---|
| `cash_guard.py` | `PASS` или `BLOCK`; код завершения 0 или 2 |
| `sell_guard.py` | `PASS` или `BLOCK` по количеству собственной позиции; код завершения 0 или 2 |
| `daily_loss.py` | `ALLOW_NEW_PROPOSALS`, `STOP_NEW_PROPOSALS` или `INSUFFICIENT_DATA`; код 0 только при разрешении новых предложений |

Успешный статус означает прохождение отдельной офлайн-проверки. Он не подтверждает прибыльность, не заменяет проверку брокерских данных и не разрешает исполнение сделки.

Первый слой нормализации запускается отдельно:

```bash
python3 skills/trader-tinvest/scripts/normalize_broker.py .local/broker-captures.json
```

[Контракт захватов и границы нормализации](skills/trader-tinvest/references/broker-normalization.md) описывает профиль `tinvest-rest-v1` для `GetPositions`, `GetInstrumentBy`, `GetMaxLots`. В нём сохраняются захваченные запросы/ответы и исходное время: без них нельзя связать лимит со счётом, UID и ценой. Секреты в захваты не включаются, сами файлы остаются вне Git. Скрипт не собирает данные из сети.

`NORMALIZED_OBSERVATIONS` и код 0 означают только преобразование формата. Поле `ready_for_validators` всегда `false`: выход не является планом и не подходит валидаторам напрямую. Данные MCP не поддержаны этим REST-профилем автоматически. У `GetPositions.securities` поле `balance` уже незаблокированное: отчётный итог равен `balance + blocked`, а не повторному вычитанию блокировки. Но даже этот итог нельзя автоматически назвать собственным рассчитанным количеством. Денежные остатки и денежные блокировки сохраняются отдельно, без предположения о доступном бюджете.

## 6. Офлайн-исследование гипотезы

```bash
python3 skills/trader-tinvest/scripts/backtest_breakout.py --help
python3 skills/trader-tinvest/scripts/backtest_breakout.py skills/trader-tinvest/references/backtest.example.json
```

[Описание модели и формата](skills/trader-tinvest/references/backtest-breakout.md) объясняет сигнал, исполнение на следующей свече, комиссии и ограничения. Пример полностью искусственный. `SIMULATED` и код 0 означают расчёт модели, а не прохождение торговых проверок. Периоды начинают с независимых копий капитала; результат не доказывает независимость выбора holdout или качество данных. Реальные данные держите вне Git, например в `.local/backtest.json`.

## 7. Проверка разработки

```bash
python3 -m unittest discover -s tests -v
```

Тесты выполняются без сети и токенов на искусственных данных. Они проверяют денежные ограничения, количество собственных бумаг, точность расчётов, свежесть входов и дневной порог. Для оценки торговой стратегии отдельно нужны исторические данные, проверочный период и учёт комиссий, спреда и проскальзывания.
