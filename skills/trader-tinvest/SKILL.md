# Координатор Trader Skill для Т‑Инвестиций

Пакет содержит 11 тематических навыков и этот координатор. Держи все 12 папок рядом: общие помощники находятся в `scripts/`, тематические контракты — в соседних навыках. Для узкой задачи загружай только подходящий `SKILL.md` и его нужные references. Если зависимость отсутствует, сообщи конкретный путь и ограничь работу доступными средствами; наличие папки не доказывает установку или доступ к MCP.

## Маршрутизация

| Задача | Навык и граница |
|---|---|
| Восстановить исторический состав, сравнить раскрытия, получить цели | [trader-copycat](../trader-copycat/SKILL.md): переданный публичный состав и проверенное отображение инструментов |
| Новости инструментов | [trader-news](../trader-news/SKILL.md): сохранённые MCP/RSS/Atom-данные, источники и дедупликация |
| Публичные раскрытия эмитентов и владельцев | [trader-pelosi](../trader-pelosi/SKILL.md): российский индекс событий; имя совместимости, не реестр сделок политиков |
| Разобрать опубликованные показатели | [trader-analyst](../trader-analyst/SKILL.md): МСФО/РСБУ и сопоставимые периоды |
| Отобрать по явным критериям | [trader-screener](../trader-screener/SKILL.md): метрики с единицами и временем доступности |
| Разложить бюджет по согласованным весам | [trader-budget](../trader-budget/SKILL.md): свои деньги, целые лоты и явные издержки |
| Сравнить портфель с целями | [trader-rebalance](../trader-rebalance/SKILL.md): свои свободные бумаги; будущая выручка не финансирует BUY |
| Проверить весь пакет предложений | [trader-risk](../trader-risk/SKILL.md): бюджет BUY, количество SELL, дневной контроль, идентичность и лимиты |
| Оформить параметры и журнал подготовки | [trader-broker](../trader-broker/SKILL.md): повторная проверка полного пакета и только DRAFT_ONLY |
| Себестоимость и результат фактических операций | [trader-tax](../trader-tax/SKILL.md): ФИФО/RUB, отдельные корзины и годы; ограниченный профиль ставок требует проверенной базы |
| Ценовые условия и состояние рынка | [trader-alerts](../trader-alerts/SKILL.md): переданные котировки/интервалы; расписание отдельно |

Общие правила переходов описаны в [контракте пакета](../../docs/porting-contract.md) для репозитория; при установке отдельных папок ориентируйся на контракты соседних навыков. Выход `budget`/`rebalance` — аналитическое предложение, а не готовый риск-пакет. Перед `risk` нужны подтверждённые источники и нормализация; булевы флаги не заменяют сверку. `broker` не записывает предполагаемые сделки в налоговый реестр.

## Режим работы и параметры

Текущий этап переноса — офлайн-CLI и искусственные примеры. Не подключай счёт, не исследуй новую стратегию и не загружай рынок только ради демонстрации установки. Для персонального анализа в отдельной задаче используй явно согласованные параметры или локальный `references/policy.local.json`. Публичный [policy.json](references/policy.json) — пример; перенос позиций, весь остаток и порог 50% не присваиваются новому пользователю автоматически. Процедура согласованного ежедневного обзора — [daily-review.md](references/daily-review.md). Параметры не создают расписания.

При отдельном запросе чтения реальных данных установи контур и счёт. Не объединяй несколько счетов молча. Найди фактически доступные инструменты официального T‑Invest MCP по их схемам, а не по наличию похожего метода API. При отсутствии подключения сообщи конкретный пробел; не восстанавливай личный портфель из публичных оценок. Для аналитики достаточно read-only доступа. Не запрашивай токен в чате и не включай его в захваты/результаты.

Вызывай только чтение. Не выставляй, не меняй и не отменяй заявки; не переводи деньги и не меняй настройки счёта/права токена. Черновики и публикация исходников не предоставляют разрешение на реальные инвестиционные операции.

## Общие инварианты данных

- Сопоставляй инструменты по UID и подтверждённому режиму торгов. Тикер служит подписью. У одного UID метаданные должны быть согласованы во всём пакете.
- Различай штуки, лоты, процентную котировку, денежную цену и НКД. Не умножай количество бумаг на размер лота повторно. Для инструментов с особой котировкой предпочитай документированную оценку брокера.
- Преобразуй `units + nano / 1000000000` и десятичную строку `value` через Decimal; сохраняй знак, валюту и исходную семантику. Разные валюты требуют явного курса и времени, а не простого сложения.
- Не называй весь остаток свободным. Отдельно учитывай собственные рассчитанные деньги/бумаги, блокировки, ожидаемые поступления и обязательства. Если доступный остаток отсутствует, вычитать блокировку допустимо только при подтверждённой семантике пересекающихся полей.
- Для контроля используй полный пакет актуальных предложений, свежие снимки и точную привязку оценки к счёту, UID, стороне, лотам и цене. `PASS` ничего не резервирует; повторный запуск не создаёт новый остаток.
- Бюджет BUY не включает ожидаемую выручку SELL. Проверка количества продажи не подтверждает её комиссию, выручку или исполнение. Короткий срок удержания не означает шорт; заёмные бумаги, маржа и обеспечение с плечом не поддерживаются текущим cash-only контуром.
- Дневной результат отделяется от пополнений/выводов; базу начала дня не сбрасывай после убытка. Доля позиции должна иметь явный знаменатель. Не подменяй доходность изменением стоимости без потоков.

В отчёте укажи данные и время, источники, выполненный модуль, результат и его пределы. `ANALYZED`, `PASS_OFFLINE`, `DRAFT_ONLY`, `LEDGER_CALCULATED` и `SIMULATED` имеют разный смысл. Подходящих предложений может не быть. Не обещай ежедневную прибыль и не выдавай арифметические тесты за преимущество стратегии.

## Необязательные расширения

Загружай соответствующие материалы, когда запрос действительно касается их:

- [Нормализация REST](references/broker-normalization.md) и [normalize_broker.py](scripts/normalize_broker.py): сохранённые `GetPositions`/`GetInstrumentBy`/`GetMaxLots`, наблюдения с `ready_for_validators:false`. Это не проверенный адаптер фактических ответов MCP.
- [Протокол стратегии](references/strategy-research.md), [контракт модели](references/backtest-breakout.md), [backtest_breakout.py](scripts/backtest_breakout.py): отдельное исследование одной гипотезы на одной акции, явный капитал, издержки и development/holdout. Искусственный пример не воспроизводит реальный счёт.
- [Профиль MOEX](references/moex-history.md), [moex_history.py](scripts/moex_history.py): публичные GET либо replay по отдельному запуску; raw и результаты остаются локально, история — `historical_unverified`. Текущие лоты и шаги не подтверждают их историческую неизменность.
- [Горизонты](references/research-horizons.md), [research_horizons.py](scripts/research_horizons.py): исторические итоги и перекрывающиеся окна, без превращения короткого результата в годовой прогноз. Учитывай подтверждённые денежные дивиденды и явно объявленные реконструкции источника.
- [Разбор upstream](references/upstream-review.md): зафиксированный исходник и карта российских замен. SEC/13F, Конгресс США, NYSE и налоговые правила США не являются российскими источниками по умолчанию.
