# Распределение бюджета

Используй этот модуль после задания пользователем целевых весов либо получения исторических целей через trader-copycat. Он сохраняет функции исходного Budget Manager: нормализацию выбранных весов, перераспределение превышения лимита доли, минимальный размер покупки, полный лот и явный остаток денег. Рубли, UID, класс торгов и размер лота заменяют долларовый формат Alpaca.

Не выбирай стратегию, лимиты риска и инструменты за пользователя. Бюджет — один явно указанный пул доступных собственных денег в одной валюте; заблокированные средства, незавершённые расчёты, займы и ожидаемые продажи в него не входят. Использование всего пула означает нулевой дополнительный резерв, но все комиссии и НКД остаются внутри бюджета.

## Запуск

Требуются Python 3.9+ и установленный рядом companion `trader-tinvest`; для ребалансировки этот модуль используется как библиотека. Найди собственную папку навыка, затем запусти:

```bash
python3 /путь/к/trader-budget/size.py /путь/к/input.json --output /путь/к/budget-result.json
```

Искусственный пример — [references/example.json](references/example.json). Он проверяет арифметику и не содержит реальных котировок или состава счёта.

## Вход и результат

- `account_id`, `currency`, `as_of` с часовым поясом и `own_cash` задают происхождение и единый денежный пул. Все денежные значения и веса — десятичные строки, не JSON-числа.
- `targets` — список `{uid, weight}`, где `weight` — доля от 0 до 1. Положительные незаблокированные веса нормализуются между собой. UID повторять нельзя.
- `instruments` — точный справочник по UID: `class_code`, `currency`, целый `lot_size`, `cost_source`; `kind` из share/bond/fund/spot_currency, `leveraged=false`, `financing="fully_paid_cash"` должны описывать установленную экономическую классификацию. Не подставляй такие значения при отсутствии данных: неизвестные и производные инструменты блокируются. Это входные утверждения источника, а не доказательство брокерской проверки.
- Пять **обязательных** строк модели: `principal_per_lot`, `fee_per_lot`, `nkd_per_lot`, `other_per_lot`, `fixed_fee`. Нулевые издержки указываются явно. Первые четыре — консервативная денежная модель одного полного лота; `fixed_fee` начисляется один раз на предложение. Для облигаций цена в процентах номинала предварительно переводится в деньги. Отсутствие издержек не означает ноль; гарантийное обеспечение нельзя выдавать за полную стоимость покупки.
- `rules.cash_buffer_fraction` — дополнительный денежный резерв, по умолчанию `"0"`; `max_position_fraction` — явный предел полной стоимости покупки относительно бюджета. Если предела нет, поле отсутствует/null, модуль не придумывает персональный лимит. Аналогично `max_order`; `min_order` по умолчанию `"0"`. `blocked_uids` исключаются.
- Превышение ограничения распределяется между оставшимися целями пропорционально весам. Непомещающиеся минимальные лоты исключаются явно; остаток после округления перераспределяется среди доступных лотов без нарушения денежного лимита. Неизрасходованные деньги из-за лотности/лимитов показаны как `rounding_or_cap_idle`.
- `proposals` содержит UID, класс, валюту, BUY, целые лоты и аналитическую стоимость. Это **не** готовый формат запроса брокеру: модуль не подделывает признаки проверки, свежие лимиты лотов или разрешение на исполнение. Исторический `as_of` сохраняется и не объявляется актуальным.

Для реального анализа получи свежие оценки точной заявки и немаржинальные лимиты брокера, затем передай нормализованные данные в trader-risk. Арифметический расчёт не устанавливает доступность инструмента, пригодность вложения или прибыльность.

Концепция адаптирована из [trader-budget исходного MIT-набора](https://github.com/jakeschincariol/trader-skill/tree/main/trader-budget). Сетевых и торговых вызовов в этом модуле нет.
